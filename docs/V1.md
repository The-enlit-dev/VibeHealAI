# VibeHeal V1: Error Explainer (web)

**Status:** built and tested locally on 2026-11-11. Not deployed. Direction approved by the owner in session on 2026-11-11 (DEC-33).

## What V1 is
A public, free page at `/fix/` on the existing static website. A vibe coder pastes an error from their terminal and gets:
1. **A plain-English explanation** from built-in, offline rules (PRODUCT.md §5).
2. **Secret redaction** of the pasted text: tokens, keys, passwords in settings and web addresses, private keys, personal folder names.
3. **A handoff brief** (HB-1 to HB-3) to copy into the user's own AI tool, with safety ground rules.

It is **not AI**, and the page says so. If no rule matches, it says "No built-in rule matches" and still produces the redacted brief.

Everything runs in the browser. Nothing is uploaded, stored or sent to any AI. There is no backend, no database, no API key and no new service, so the extra cost is $0 (DEC-05, DEC-22).

## Rule families
Missing package or file (incl. `@/` aliases, scoped packages), wrong letter case, port in use, missing environment variable (names only), Node.js version mismatch (incl. `ERR_REQUIRE_ESM`), TypeScript errors (`TSxxxx` and Next.js `Type error:`), npm dependency conflicts (`ERESOLVE`, `EINTEGRITY`), command not recognised, wrong folder (no `package.json`), locked files on Windows.

**Coverage is unmeasured (unknown U2).** The rules are tested on realistic samples written for this project, not on a real-world collection. Expect misses.

## Code map
| Path | Role |
|---|---|
| `shared/explainer/` | The core (TypeScript, pure functions, no I/O): `redact.ts`, `package-facts.ts`, `rules.ts`, `brief.ts`, `explain.ts` |
| `shared/explainer/explainer.test.ts` | Vitest tests (rules, redaction with runtime-generated fake secrets, validation, hostile input) |
| `scripts/build-fix-core.mjs` | Strips types with Node's built-in `stripTypeScriptTypes` into `website/fix-core/*.js` (no dependencies). `--check` fails if out of date |
| `site/pages/fix.html`, `website/fix.js` | The page and its browser script (DOM built with `textContent`, no `innerHTML`) |
| `scripts/build-site.mjs` | Generates `website/fix/index.html` and adds the page to the sitemap |

The desktop app can import `shared/explainer` directly later (M1 to M3), so the same rules serve both.

## Run locally
```bash
npm install
npm run build:fix        # website/fix-core/ from shared/explainer/
npm run build:site       # website/ from site/
npm run site:dev         # http://127.0.0.1:8790/fix/
npm run check            # typecheck, lint, site checks, tests, build
```

## Environment variables
**None.** V1 needs no keys or settings. `.env.example` is for the separate local integration backend and is unchanged.

## Deploy (owner action: nothing is deployed by Claude Code)
The site already deploys to Netlify from this repository (`netlify.toml`). The build command now runs `node scripts/build-fix-core.mjs && node scripts/build-site.mjs`, so merging this branch publishes `/fix/` on the next Netlify deploy. No new Netlify setting is needed. To preview first, open the pull request: Netlify builds a deploy preview.

After deploying, check on the live URL: the page loads, an example explains, **Copy the brief** works, and the browser console shows no Content-Security-Policy errors (the CSP in `netlify.toml` allows the page's module script from the site itself).
