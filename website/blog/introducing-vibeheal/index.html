Introducing VibeHeal

The project now has a name, VibeHeal, and a catch line, "Just vibeheal it." Here is what it is meant to do, what exists today and what is still undecided.

5 November 2026 · The VibeHeal team

The project now has a name: VibeHeal. The catch line is "Just vibeheal it." This post explains what the project is meant to do, what exists today, and what is still open.

What VibeHeal is meant to do

VibeHeal is a planned assistant for vibe coders: people who build apps, websites and software with AI tools such as Claude Code and Cursor. The hard part of vibe coding is often not the first version. It is what happens next:

  • a change from an AI tool breaks something, and it is not clear what changed;
  • an error message makes no sense;
  • the project depends on hosting, a database and design tools that each have their own dashboard;
  • the same chores come back every week.

VibeHeal aims to help with that wider workflow while your own AI tool keeps writing the code.

What exists today

Nothing is available to download yet. What exists is an early development foundation: a local backend, an integration platform and a read-only GitHub connection. It is tested by the developer with automated tests against a simulated GitHub API. It is not a public release.

The home page lists every planned capability with an honest status: in development, planned or exploring.

Principles we are keeping

  • Your AI tool does the coding. VibeHeal does not run or bill for its own AI model today.
  • You stay in control. Changes should be reviewable, and it should always be possible to go back.
  • Read-only first. Connections to other services start with read-only access.
  • No made-up claims. If something is not built yet, the site says so.

What happens next

The next steps are in the open: project understanding and debugging help, code safety and recovery, and more integrations. Release date and pricing are not decided.
